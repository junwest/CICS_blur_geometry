## 1. 실험 조건

### 1.1 데이터·전처리 (base와 동일, 재확인 결과)
HPatches Test 24쌍(12 시퀀스: illumination 6, viewpoint 6), 회색조 변환(BGR2GRAY) 후 긴 변 960 px 이하로 INTER_AREA 축소(확대 없음),
화소 중심을 고려한 H 변환 H_r = S_t·H·S_r⁻¹, 유효 여백 24 px(평가 영역이자 검출 mask). 블러 8조건: Gaussian σ1.5/3.0,
Disk r3/r5, Motion 길이 9/17 px × 0°/90°. 설정 파일과 base 보고서의 값이 일치함을 확인했다. ORB/SIFT는 base "default"
설정이다(OpenCV 기본값에서 nfeatures만 1500; OpenCV 자체 기본값은 ORB 500, SIFT 0). 매칭: BF knn k=2, ratio 0.75.
RANSAC 3 px / 2000회 / 0.995, 매 추정 전 `cv2.setRNGSeed(42)`.

### 1.2 비교군과 정보 조건

| 방법 | 받는 정보 | 고정값 |
|---|---|---|
| B (무처리) | — | — |
| Unsharp | 커널·학습 데이터 없음, 세부 대비 강조 | α 1.0, σ 1.2, truncate 4 (base 값) |
| Wiener–Hunt (Known-PSF) | 생성에 쓴 **정확한 커널** | balance 0.005 (base 검증 선택값, 8조건 모두; 후보 격자의 경계값) |
| NAFNet | 학습된 사전정보, **커널 정보 없음** | 공식 GoPro-width32, 재학습·미세조정 없음, 사전학습 비용 알 수 없음 |
| Clean | 기준 성능 | — |

NAFNet 입출력: 회색조 uint8 → /255 → 3채널 동일 복제(R=G=B) → NAFNetLocal(공식 테스트 옵션, 전체 영상, 내부에서 오른쪽·아래로
16의 배수까지 zero padding 후 `[:H,:W]` crop) → 공식 tensor2img(clamp, ×255, round) → `cv2.COLOR_BGR2GRAY`. 어떤 방법에도 색 정보를
주지 않았다. 출처: megvii-research/NAFNet @ 2b4af71, 가중치 공식 gdrive(sha256 19394e61…), strict load, 17.1 M parameters.

NAFNet 학습 분포와의 차이: GoPro는 RGB, 1280×720, 고속 프레임 평균으로 합성한 카메라 흔들림·물체 운동 블러다. 이번 입력은
회색조를 3채널로 복제했고, 합성 균일 Gaussian/disk/직선 모션 블러이며, 8-bit로 양자화했다. 이 결과는 한 모델의 결과이며 학습 기반
복원 전체를 대표하지 않는다. 또한 학습 기반 **복원**을 평가한 것이지 학습 기반 **직접 매칭**(learned feature/matcher)과 비교한 것이 아니다.

### 1.3 실험 구성

- **Exp1 (주실험)**: 기준 영상 = Clean(detectAndCompute, base와 동일). 대상 영상에서 첫 글자 = 검출 영상, 둘째 = 기술자 영상.
  BB(공통 기준선, 1회), BR, RB, RR × {Unsharp, Wiener, NAFNet}. 24쌍 × 8블러 × 2검출기 = 384셀; 3888행.
- **Exp2 (양쪽 블러, 대표 조건)**: 17 px 모션. same = 기준 0° / 대상 0°, diff = 기준 90° / 대상 0°. 양쪽 무처리 / 기준만 /
  대상만 / 양쪽 처리. 전체 파이프라인. 24쌍, 960행.
- **Exp3 (Wiener 커널 불일치)**: 실제 블러 17 px 0°, 제공 커널 exact / 길이 13 / 길이 21 / +5° / +15°(결과 확인 전에 고정; 끝점 횡변위 0.74 / 2.20 px), balance 0.005. 24쌍, 240행.
- Exp2와 Exp3는 교차하지 않았다. 검출기 튜닝(base 그룹 B)은 확장하지 않았다.

### 1.4 통계
단위는 셀(pair, blur, detector) 안의 대응 차이다. 블러 8조건을 쌍별로 평균한 뒤(n = 24쌍) 시퀀스 단위 클러스터 부트스트랩(12 클러스터,
5000회, seed 42)으로 95% CI를 구했다. 성공/실패는 실패 셀을 포함한 전체 셀에서 계산했다. 연속 H 오차(log10)는 비교하는 두 조건 모두 유효
H를 얻은 **공통 유효 셀**로 한정했다(표에 n쌍 표시). gained/lost 셀 수와 McNemar p는 셀이 독립이 아니므로 기술적 수치다.

**관찰.** (i) Wiener·NAFNet은 검출 영상 교체(RB−BB, RR−BR)의 효과가 기술자 영상 교체(BR−BB, RR−RB)보다 컸다. (ii) 기술자 영상 교체의
효과는 검출 영상이 R일 때(RR−RB)가 B일 때(BR−BB)보다 컸다. GT-correct 기준으로 Wiener ORB +49.6 vs +9.1, NAFNet SIFT +53.2 vs −3.3이다.
(iii) NAFNet의 BR−BB는 GT-correct가 약간 줄었다. (iv) Unsharp는 모든 대비에서 작았다.

**해석상 제약.** BR−BB와 RR−RB만 검출 결과를 고정한 기술자 효과다. RB−BB와 RR−BR에는 키포인트 수(예: SIFT 평균 818개 → Wiener 1285개),
위치, 분포, 크기, 방향이 함께 바뀐 효과가 섞여 있어, 위치 정확도 효과라고 할 수 없다.

**가능한 설명(검증 안 됨).** 기준 영상이 Clean이므로, R에서 검출한 키포인트는 크기·방향이 Clean 검출과 더 비슷하고(5절: 같은 octave 비율,
방향 차), 같은 크기·방향으로 R에서 계산한 패치가 Clean 패치에 더 가까울 수 있다. B에서 검출한 키포인트는 크기·방향 자체가 Clean과 달라,
기술자 영상만 바꾸어서는 맞추기 어려울 수 있다.

처리하면 same·diff 모두 높은 성공률을 보였고, Exp1의 Clean 기준 RR과 비슷한 수준이었다(diff 양쪽 Wiener ORB 18 vs Exp1 RR 18; SIFT 21 vs 21).
(iv) Unsharp는 거의 변화가 없었다.
**가능한 설명.** 같은 커널로 흐린 두 영상은 서로 비슷한 외관을 가지므로, 매칭에는 두 영상의 **일치 정도**가 중요하다. 한쪽만 복원하면 이 대칭이 깨진다.
이번 결과는 "복원은 기준 영상이 블러여도 항상 유리하다"를 지지하지 않는다. **양쪽에 같은 처리를 하는 조건에서** 효과가 유지되었다.
대표 조건 하나(17 px 모션, 직교 방향)의 결과다.

## 10. NAFNet 출력 발산과 정렬 점검 (구현·모델 동작 보고)

### 10.1 발견
240장 중 23장에서 raw 출력이 [0,1]을 크게 벗어나 입력과 무관한 격자 모양 포화 패턴이 되었다(예: Clean 대상 i_gonnenberg__1-2, 범위 −25 ~ +24,
출력 vs 입력 PSNR 5.4 dB). 블러 대상 13장은 모두 Gaussian σ1.5(9), σ3.0(2), disk r3(2)였고, 모션 블러 입력(대상 96장 + 기준 24장)에서는 0장이었다.
Clean 대상은 10/24장이 발산했다. **NAFNet은 선명한 입력에서 항등에 가깝게 동작하지 않았다.**

### 10.2 구현 오류 여부 점검 (`tools/nafnet_diag*.py`, DECISIONS C15)
- float64 CPU 실행과 fp32 GPU 실행의 출력이 같다 → 정밀도 문제가 아니다.
- TLC(local pooling) 없는 NAFNet도 발산한다.
- 학습 패치 크기 256×256 crop에서도 발산한다 → TLC·패딩·영상 크기 문제가 아니다.
- 원본 컬러 영상(i_gonnenberg, i_castle)에서도 발산한다 → 회색조 복제만의 문제가 아니다.
- 공식 demo 영상에서는 정상 범위 출력이 나온다. 체크포인트 sha256이 공식 값과 같고 strict load도 통과했다.
- 블록별 활성값을 추적하면 level-3 인코더 28블록 구간에서 최대 |활성값|이 약 1e3에서 3e4로 커진다.
따라서 공식 절차로 실행한 이 모델의 실제 동작으로 판단했다. 원인은 검증하지 않았다(학습 분포 밖의 선명·약블러 입력에서의 활성값 폭주는 가설).

### 10.3 정렬
출력 크기는 240/240 입력과 같다. 패딩은 오른쪽·아래에만 붙고 `[:H,:W]`로 잘라내므로 원점 이동은 구조상 없다. 전역 LS 이동 추정(base 테스트의 추정기)은
모션 블러 입력에서 중앙값 약 0.01 px였다(대조군 Wiener ≤ 0.006 px, B ≤ 0.056 px). Gaussian/disk 입력에서는 발산하지 않은 출력도 영상별로 −1 ~ +1.9 px의
겉보기 이동을 보였고(Gaussian σ1.5 중앙값 (−0.47, +0.50) px), 키포인트 평균 이동(5.3절)과 방향이 같았다. 이 추정기는 순수 평행이동을 가정하므로, 정렬 오류인지
비평행이동 복원 변화인지는 **확인하지 못했다**.

### 10.4 결과에 미치는 영향 (`T13b_nafnet_flag_outcomes.csv`, `T3_sensitivity.csv`)
발산 셀(검출기당 13셀)의 RR 성공은 ORB 1/13, SIFT 3/13이었다(BB 11/13, 12/13). 발산하지 않은 179셀에서는 RR 67.6% vs BB 44.7%(ORB), 86.0% vs 67.6%(SIFT)였다.
민감도 분석에서 발산 셀을 빼면 RR−BB가 ORB +24.0 pp [+17.4, +32.1], SIFT +18.5 pp [+12.2, +24.7]였고, BR−BB는 ORB +10.8 pp [+5.3, +16.1]이었다.
**주결과는 모든 셀을 포함한 값이다.**

## 13. 관찰 · 가능한 설명 · 확인하지 못한 부분

**관찰(측정됨)**
1. Wiener(정확 커널) > NAFNet > Unsharp 순으로 RR−BB 개선이 컸다(Success, GT-correct, coverage 모두). Unsharp SIFT는 0과 구분되지 않았다.
2. 개선은 주로 검출 영상을 R로 바꿀 때 나타났고, 기술자 영상의 효과는 R 검출과 함께일 때 컸다.
3. 복원은 Clean 정답 대응점의 3 px 안 재검출을 늘렸고, 재검출된 점은 대부분 같은 위치로 정답 매칭되었다. 기준 집합 밖의 새 정답 매칭도 전체의 16–34%를 차지했다.
4. SIFT의 Clean 대비 위치 변화는 Wiener에서 가장 작았다. NAFNet은 모션 블러에서 작았고, Gaussian/disk에서는 B보다 컸다.
5. 위치만 바꾼 고정 랜드마크 H의 개선은 같은 셀 파이프라인 개선보다 작았다(SIFT).
6. 양쪽 블러에서는 한쪽만 복원하면 불리했고, 양쪽을 처리하면 유리했다. Wiener는 커널 길이·방향 오류에 민감했다.
7. NAFNet은 일부 선명·약블러 입력에서 출력이 발산했고, 그 셀은 매칭에 실패했다.

**가능한 설명(검증 안 됨)**
- 복원의 주 효과는 대응점 수·비율 확보(outlier 감소)와 Clean 검출과 비슷한 크기·방향의 키포인트를 얻는 데 있을 수 있다. 위치 정밀도 개선은 부차적일 수 있다.
- 매칭은 두 영상 외관의 일치에 의존하므로, 기준이 Clean일 때는 대상 복원이, 양쪽이 블러일 때는 양쪽의 같은 처리가 유리하다.
- NAFNet의 Gaussian/disk 성능 저하와 겉보기 이동은 학습 분포(모션 블러)와의 차이와 관련될 수 있다.

**확인하지 못한 부분(추가 검증 필요)**
- 위치·대응점 수·공간 분포의 효과 분리: 세 요인이 강하게 상관되어 이 자료로는 분리할 수 없다. 개입형 실험(예: 같은 대응점 집합에서 분포만 바꾸기, 같은 위치에서 수만 바꾸기)이 필요하다.
- 3 px 밖의 위치 변화, ambiguous 연결 원소의 정체성, ORB의 위치 분석(표본 부족).
- NAFNet 발산의 원인과 Gaussian/disk 입력의 겉보기 이동이 정렬 오류인지 여부.
- 잡음·실제 블러·공간 변화 블러에서의 일반화(이번은 잡음 없는 합성, 8-bit 양자화만).
- Exp2·Exp3는 대표 조건 하나(17 px 모션)다. 다른 블러 종류·강도에서는 확인하지 않았다.
- Unsharp는 고정 설정 하나, NAFNet은 모델 하나의 결과다.
- "잘못된 위치에 복원된 구조가 있어도 H가 좋아질 수 있는가": Clean과 일치하지 않는 변화(엣지 FP 증가, Gaussian σ1.5에서의 위치 이동, 발산 출력)는 관찰했다.
  그러나 이것이 물리적으로 잘못된 구조인지는 판정하지 않았다. 발산 셀에서도 H가 좋아진 사례가 1건 있었지만(7.2절 SIFT 50%), 발산 셀 전체로는 대부분
  실패했으므로(10.4절) 일반화할 수 없다.

## 15. 가우시안 표현(Gaussian splatting 등) 기반 복원 검토를 위한 메모 — 실행하지 않음

이번 결과에서 남은 문제와, 그 방법을 검토하려면 먼저 확인해야 할 점만 정리한다.
1. **비교 기준의 정보 조건**: 이번 Wiener는 정확 커널을 받았고, 커널 오류에 매우 민감했다(9절). 가우시안 표현 방법이 커널·다시점·카메라 포즈 중 무엇을
   입력으로 받는지 먼저 정하고, 같은 정보를 받는 기준선(예: 같은 커널 추정치를 받는 Wiener)을 함께 두어야 한다.
2. **다시점 입력의 필요성**: HPatches 쌍은 시점 2개(기준 1 + 대상 1)뿐이다. 다시점 재구성을 쓰는 방법이라면 입력 시점 수와 평가 쌍이 겹치지 않게 분리하는
   설계가 필요하다(평가 대상 영상을 재구성에 쓰면 정보 누수).
3. **좌표 정렬 검증**: NAFNet에서 Gaussian/disk 입력의 겉보기 이동을 확인하지 못했다(10.3절). 렌더링 기반 복원은 카메라 모델·래스터화 규약 때문에
   서브픽셀 이동이 생길 수 있으므로, 이번의 전역 이동·키포인트 평균 벡터 점검에 더해 정렬 기준(예: 합성 패턴의 대칭성 시험)을 먼저 마련해야 한다.
4. **분리해야 할 효과**: 이번 분해에서는 대응점 확보 효과가 위치 효과보다 커 보였지만 분리되지 않았다(7.1절). 새 방법도 BB·BR·RB·RR 분해와 고정 랜드마크 진단을
   그대로 적용해야, 영상 품질 향상과 기하 정합 향상의 관계를 같은 틀로 비교할 수 있다.
5. **양쪽 블러 조건**: 한쪽만 복원하면 불리했다(8절). 기준·대상 모두에 같은 방법을 적용하는 조건을 기본으로 포함해야 한다.
6. **실패 감시**: 학습 기반 모델처럼 입력 분포 밖에서 발산하거나 항등에서 벗어날 수 있으므로, Clean 입력 항등성 점검과 출력 전용 이상 규칙을 미리 정해야 한다.
7. **비용 기록**: 장면별 최적화 시간·장치, 사전학습 여부를 같은 시간 측정 범위로 기록해야 한다.
